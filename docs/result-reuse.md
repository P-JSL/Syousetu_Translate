# 완료 번역의 정확한 재사용

v0.3.6 이후 개발 소스의 기능입니다. 같은 원문을 다시 번역하거나 중단한 작업을
다시 실행할 때, 완료된 결과를 로컬에서 재사용합니다. 처음 보는 문장의 추론을
생략하는 기능과 구분하며, 재번역의 개선율을 첫 번역의 90~95% 달성으로 표시하지 않습니다.

## 적용과 무효화

CLI/GUI 내부 엔진의 기본 설정 `reuse_translations=true`를 사용합니다.
GUI 설정의 **저장된 번역 결과 재사용**을 끄거나 CLI에 `--no-result-cache`를
주면 새로 처리합니다. 라이브러리는 기본 비활성화이며 다음처럼 명시합니다.

```rust,ignore
let mut translator = OfflineTranslator::builder(model_directory)
    .memory(memory)
    .translation_cache(result_directory)
    .build()?;
```

식별자에는 실행 파일 SHA-256, 전체 교정 기억 스냅샷, 처리 방식·문맥 수·CPU 예산,
OS·아키텍처·사용한 x86 명령 지원이 들어갑니다. 실행 파일 해시는 고정 모델
매니페스트와 토크나이저·생성·언어 처리 코드도 묶습니다. 모델 메타데이터와 GGUF의
전체 SHA 검증은 재사용 파일을 열기 **전에** 그대로 실행합니다.
모델이나 코드·사용자 교정·설정이 바뀌면 별도 식별자를 사용합니다.

원문은 UTF-8 문자열 전체로 비교합니다. 부분 문자열이나 유사한 문장으로 다른
결과를 가져오지 않습니다. 원래 엔진이 정상 완료한 최종 결과만 저장하고, 사용자
교정과 사전의 우선순위 및 원문의 순서를 유지합니다. 이 데이터는 신경망 학습이나
승인된 교정 기억으로 가져오지 않습니다. 원래 모델의 오역 자체를 고치지는 않습니다.

## 파일과 실패 처리

기본 위치는 사용자 데이터 폴더의 `translation-cache`이며 출력 TXT와 별개입니다.
원문·번역 내용이 포함된 로컬 압축 파일로, 외부로 전송하지 않습니다. CLI의
`--result-cache-dir PATH`로 위치를 정할 수 있습니다.

- 식별자별 16,384개와 원문·번역·항목 비용 합 16MiB를 상한으로 둡니다.
  한 항목의 원문 4KiB/번역 8KiB를 넘으면 새로 계산하며 저장하지 않습니다.
- 잠금 후 현재 파일을 재조회하고, 이 실행에서 완료한 변경분만 병합합니다.
  서로 다른 실행이 같은 파일을 열어도 다른 실행의 완료 결과를 덮어 없애지 않습니다.
- 512개 단위와 정상 종료 때 저장합니다. 취소·비정상 종료 때 마지막 미저장 결과는
  다시 계산할 수 있으며, 완료된 TXT 접두부 보존 계약은 바꾸지 않습니다.
- 손상·출처 불일치·쓰기 실패는 재사용을 포기하고 새로 번역합니다. 파일과 백업을
  임의로 지우지 않고, 잠금이 풀린 뒤 미저장 변경분을 다시 시도할 수 있습니다.
- 모든 입력이 준비된 경우 자동 성능 확인을 위해 일부 문장을 다시 계산하지 않습니다.
  실시간 TXT 출력·문단·회차 순서는 기존 스트리밍 경로로 처리합니다.

여러 식별자의 옛 파일을 자동 삭제하지 않습니다. 재사용을 끄는 것은 파일 삭제와
다릅니다. 사용자가 교정한 문장을 삭제하면 교정 스냅샷이 바뀌므로 이전 결과도
재사용되지 않습니다.

## 검증과 측정

압축 파일의 출처·항목 상한, 손상 데이터 보존, 중단된 교체의 백업 보존, 잠금 경합,
서로 오래된 스냅샷을 가진 실행들의 변경분 병합을 시험했습니다. 실제 고정 모델로
재사용 전후의 동일 출력, 조회 미적중 0회, 사용자 교정 변경 시 무효화, 모델 없이
재사용으로 우회하지 못하는 것을 확인했습니다. production/legacy 회귀와 Clippy도
별도로 실행했습니다.

성능 재현 도구는 `examples/benchmark_result_reuse.rs`입니다. 캐시 없는 대조 1회,
비어 있는 결과 폴더 3회, 각각을 재사용하는 새 프로세스 3회를 번갈아 실행합니다.
모든 TXT의 SHA-256을 대조 결과와 비교하고, 별도의 `verify_saved_novel`로 전체
원문 행·회차·문단 구조를 확인합니다. OS 파일 캐시는 비우지 않습니다.

2026-11-16, AMD EPYC 9V45의 CPU 예산 4개·GPU 없음 조건에서 측정했습니다.
추론 중 다른 빌드나 모델 시험은 병행하지 않았습니다. 아래 수치는 128개 문맥의
병렬 정책이며, 기본 GUI 32개 자동 정책이나 여러 PC의 평균이 아닙니다.

| 작품 | 빈 결과 폴더 3회 중앙값 | 재사용 3회 중앙값 | 재번역 시간 감소 | 전체 TXT |
| --- | ---: | ---: | ---: | --- |
| [35화](result-reuse-35.json) | 52.8494초 | 0.6914초 | 98.6918% | 6,248행, 모든 실행 동일 |
| [24화](result-reuse-24.json) | 80.7048초 | 0.7575초 | 99.0613% | 17,041행, 모든 실행 동일 |

첫 실행에서는 이전 파일의 결과를 불러온 항목이 0개였습니다. 재사용 실행에서는
각각 3,276개/7,994개의 완료 결과를 불러왔고, 조회 미적중은 모두 0회였습니다.
각 작품의 대조 1회·빈 폴더 3회·재사용 3회, 총 14개 전체 TXT가 각 작품의 대조와
바이트 단위로 같았습니다. 결과에는 모델 로드·해시 검증·파싱·목차와 본문 처리·
최종 TXT 저장·재사용 파일 저장 및 프로세스 종료가 포함됩니다.

캐시 없는 대조는 각각 59.8124초/76.5718초의 단일 측정입니다. 빈 폴더 실행은
범위 51.5281~56.3629초/79.0660~87.6275초였습니다. 이 변동과 저장 비용 때문에
첫 번역이 빨라졌다는 근거로 사용하지 않습니다. 원래 v0.3.2 기준의 첫 번역
90% 목표(16.3111초/26.3902초)와 95% 목표(8.1555초/13.1951초)는 **아직 미달**입니다.

기존 모델 비교 명령을 보존하기 위해 `--no-learning`은 디스크 결과 재사용도
비활성화합니다. 교정 기억 없이 재사용만 측정할 때는 `--reuse-results`를 함께 줍니다.
이 구분을 생략하고 캐시 적중을 모델 추론 속도 향상으로 계산하지 않습니다.

```sh
cargo build --locked --release --features gui --bins \
  --example verify_saved_novel --example benchmark_result_reuse
cargo run --locked --release --example benchmark_result_reuse -- \
  CLI MODEL URL INDEX_HTML EPISODE_DIR CHAPTERS ORIGINAL_SECONDS NEW_OUTPUT_DIR
```

이 기능은 원래 번역 함수와 모든 입력 조건이 같을 때 같은 결과를 재사용하는
메모이제이션입니다. 실행 파일과 검증된 고정 모델을 묶는 출처 추적은
[SLSA provenance](https://slsa.dev/spec/v1.2/provenance)의 출처 식별 원칙을 참고했습니다.
이 설계를 신경망의 의미 정확성이나 모든 장비의 성능 보장으로 해석하지 않습니다.
