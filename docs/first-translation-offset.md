# 첫 번역의 INT8 보정 연산 사전 계산

2026-11-17(KST), `b31e6ac`의 내부 엔진과 비교한 후속 개발 소스입니다.
**첫 번역의 90~95% 시간 단축 목표는 아직 미달입니다.** 이번 기록은 디스크
번역 결과와 교정 기억을 끈 첫 번역의 개선이며 재번역 가속을 포함하지 않습니다.

## 전체 작품 비교

동일한 두 실행 파일을 번갈아 실행하는
[`benchmark_first_translation`](../examples/benchmark_first_translation.rs)을 추가했습니다.
각 작품에서 대조·수정 버전을 3회씩 새 프로세스로 실행합니다. 2번째 쌍은 순서를
뒤집어 실행 순서의 영향을 줄입니다. 모델 전체 무결성 확인·로드·파싱·모든 화의
번역·최종 TXT 저장과 프로세스 종료까지 포함합니다.

AMD EPYC 9V45, CPU 예산 4개, GPU 없음, 논리 문맥 128개, 병렬 정책 고정입니다.
HTML은 사전 저장한 같은 자료이며 네트워크 다운로드와 대기는 제외했습니다.
OS 파일 캐시는 비우지 않았고, 추론 중 다른 CPU 빌드·모델 시험을 병행하지 않았습니다.

| 작품 | 현재 소스 대조 중앙값 | 수정 중앙값 | 이번 변경의 시간 감소 |
| --- | ---: | ---: | ---: |
| [35화 원자료](first-translation-offset-35.json) | 43.7815초 | 42.1416초 | 3.7457% |
| [24화 원자료](first-translation-offset-24.json) | 62.9972초 | 61.1272초 | 2.9683% |

모든 쌍에서 수정 버전이 짧았지만, 표본은 장비 1대의 각 3쌍입니다. 실행 간
변동이 있으며 모든 PC의 최소 개선율·평균·신뢰구간을 보장하는 결과가 아닙니다.
첫 탐색 비교 35화 48.75→44.40초는 이 반복 측정 표본과 섞지 않았습니다.

12개 TXT 모두 각 작품의 대조와 바이트 단위로 같았습니다. 별도
`verify_saved_novel`로 35화 원문 6,248행/24화 17,041행, 전체 회차·문단·저장
순서와 비어 있지 않은 번역을 검증했습니다. 출력 동일성은 기본 모델의 오역을
고치거나 인간 수준의 자연스러움을 증명하는 지표가 아닙니다.

이전 v0.3.2 기록 163.1107초/263.9015초 대비 수정 중앙값의 감소는
74.1638%/76.8371%입니다. 과거 실행 파일을 이번에 다시 측정한 수치는 아니며,
이번 코드 변경의 개선율은 위 표의 약 3~4%입니다. 기존 90% 목표
16.3111초/26.3902초와 95% 목표 8.1555초/13.1951초에는 도달하지 못했습니다.

## 계산과 정확성

기존 Q8_0 경로는 부호 있는 가중치 `w`를 `w+128`로 저장하고, 활성값 `a`와
곱한 뒤 매 32개 블록마다 `128·Σa`를 보정했습니다. 수정 경로는 다음 항등식을
사용합니다.

```text
Σ(w·a) = Σ(w·(a+128)) − 128·Σw
```

`−128·Σw`는 가중치에만 의존하므로 로딩 때 패킹하며 한 번 계산합니다.
활성값은 원래 BlockQ8K의 반올림·스케일·코드를 계산한 뒤, 커널 밖에서 코드의
최상위 비트만 반전합니다. 커널은 이 보정 정수로 누산기를 초기화하고 signed
weight × unsigned activation의 VNNI 내적을 수행합니다. Q4K/Q6K와 VNNI 없는
CPU의 기존 연산 경로는 유지합니다.

`w,a ∈ [-128,127]`에서 32개 원소의 보정값 절댓값은 최대 524,288입니다.
unsigned 내적 및 보정을 포함한 중간 정수의 절댓값도 1,568,768 이하로 INT32
범위에 들어갑니다. 기존 F32 보정 과정의 정수도 `2^24`보다 작아 정확히 표현됩니다.
따라서 새 정수 내적의 F32 변환은 기존 변환·보정과 같고, 뒤따르는 블록별
가중치·활성 스케일 곱과 FMA 누산 순서를 그대로 유지합니다. 다른 모델 정밀도나
가중치·어휘 축소, beam 변경을 사용하지 않습니다.

공식 [gemmlowp의 offset 처리 설계](https://github.com/google/gemmlowp/blob/master/doc/low-precision.md#efficient-handling-of-offsets)는
영점 보정항을 행·열 합으로 분리하고 패킹 단계에서 준비하는 원리를 설명합니다.
이를 현재 Q8 블록·스케일·누산 순서에 맞게 Rust로 적용했습니다. gemmlowp를
의존성으로 추가하거나 해당 프로젝트의 성능을 우리 측정치로 인용하지 않습니다.

추가한 독립 시험은 공개 QTensor 바이트의 원래 signed 코드로 32개 원소 정수
내적과 스칼라 FMA를 직접 계산해, 새 커널과 비트 단위로 비교합니다. 영 입력,
양수·음수·혼합 활성값, 1/7/65/257행과 256/1024/4096열을 포함합니다.
별도 실행으로 AVX-512 VNNI와 AVX-VNNI 경로를 확인합니다. 기존 행 변경·재배열,
전체 어휘 선택·동점·반복 금지, 활성값 반올림 시험도 유지합니다.

Linux의 production 릴리즈·legacy 전체 회귀와 Clippy `-D warnings`를 통과했습니다.
고정 모델을 사용한 대화·금지 표현, 256개 문맥의 순서와 순차/병렬 동일성,
사용자 교정 우선순위·재사용 무효화 시험 5개도 통과했습니다. Windows 실모델
처리 시간과 GPU 성능은 이 측정에 포함되지 않습니다.

## 메모리와 배포 범위

가중치 타일의 보정 정수 벡터로 타일 크기가 576→640바이트가 되어 패킹된
Q8_0 가중치만 약 11.1% 늘어납니다. 전체 모델 파일의 크기와 SHA, 토크나이저,
필수 의존성은 바뀌지 않습니다. 첫 35화 탐색 실행의 peak RSS 표본은 대조
1,226,876KiB/수정 1,269,832KiB였습니다. 이는 1회 표본이며 여러 PC 평균이나
전체 반복 측정의 메모리 중앙값이 아닙니다.

측정에 사용한 기본 CLI 실행 파일은 10,683,344→10,663,928바이트였습니다.
유지보수용 벤치마크·원고·로그는 배포 파일 목록에 포함하지 않습니다.
이 문서는 개발 소스의 결과이며 공개된 v0.3.6 ZIP의 교체를 뜻하지 않습니다.

## 재현

```sh
cargo build --locked --release --example benchmark_first_translation \
  --example verify_saved_novel
target/release/examples/benchmark_first_translation \
  CONTROL_CLI CANDIDATE_CLI MODEL WORK_URL INDEX_HTML EPISODE_DIR \
  CHAPTERS ORIGINAL_REFERENCE_SECONDS NEW_OUTPUT_DIR
```

새 폴더만 사용하며 모든 샘플에 `--no-learning --no-result-cache`를 지정합니다.
파일과 모델 SHA가 측정 도중 바뀌거나, 저장된 TXT가 달라지거나, 독립 구조 검증이
실패하면 정상 결과로 보고하지 않습니다. 각 성공 샘플을 즉시 기록해 중단된
실험과 완성된 실험을 구별합니다.
