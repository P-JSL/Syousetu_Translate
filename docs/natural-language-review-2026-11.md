# 공통 번역 처리와 자연스러운 한국어 검토

검토일: 2026-11-16 (KST). GitHub main `1c8ee5d`의 README와 개선 계획을
보존한 상태에서 언어 처리와 교정 기억을 보완했습니다. 번역 모델의 가중치,
토크나이저, INT8 정밀도, 전체 어휘와 병렬 추론 방식은 변경하지 않았습니다.

## 실제 적용 범위

내부 SMaLL-100 모델은 기존과 같이 토큰화 전 일본어 축약형을 처리하고,
생성 후 한국어 말투와 문장부호를 정리합니다. CLI의 `native`와 `eztrans`
호환 경로도 이제 같은 처리를 사용하며, 교정 기억도 공유합니다.
다른 `Translator` 구현체는 `Pipeline::with_natural_text().with_memory(memory)`로
동일한 경로를 사용할 수 있습니다. 새로운 외부 LLM 서비스 연동을 추가한 것은
아닙니다. 원본 엔진 비교 API와 명시적인 EHND 실험 경로는 그대로 유지합니다.

처리 순서는 다음과 같습니다.

1. 직접 지정한 필터 사전의 일치 여부를 확인합니다. 해당 표현의 철자와 공백을
   후처리가 다시 바꾸지 않도록 보호합니다. 축약형 확장 후 생기는 사전 일치도
   같은 보호를 받습니다.
2. 정확히 일치하는 교정 기억이 있으면 엔진 추론 전에 반환합니다. 사용자 교정의
   문장·말투·공백을 새 후처리로 덮어쓰지 않습니다.
3. 확인된 일본어 축약형만 확장합니다. 진행·완료·부정·의무·부탁을 구분하고,
   표현 자체를 설명하는 문장에는 확장을 적용하지 않습니다.
4. 생성된 한국어에는 원문에서 확인되는 반말/존댓말, 부정형 종결, 감사·응답,
   호칭, 질문·감탄·말줄임표를 제한적으로 복원합니다. 단어 사이의 공백은
   유지하며 한 원문 단위 안의 불필요한 연속 공백과 줄바꿈을 정리합니다.
5. 원문 단어와 이전 한국어 표기가 모두 일치하는 용어 교정을 마지막에 적용합니다.
   호환 경로의 여러 줄 입력에는 용어 위치를 추측하여 교차 적용하지 않습니다.

문단 수와 빈 줄 위치가 일치하는 여러 줄 결과는 원래 경계와 CRLF를 보존합니다.
줄 대응이 맞지 않으면 새 문단 구조를 추측하지 않습니다. 따옴표 중복 제거도
균형이 잡힌 내부 인용과 원문에 명시된 중첩 인용을 보존하도록 제한했습니다.

## 단어와 표현의 범위

기존 1,058개 표제어 사전과 기본 교정에 더해, 발화 기본값은 112개에서
**292개**로 늘었습니다. 새 180개는 프로젝트에서 별도로 작성하고 의미·부정·
높임말을 검토한 전체 발화입니다. 감사, 위로, 사과, 분노, 부끄러움, 독백,
망설임, 부탁, 허용, 금지, 의무, 일상 표현과 명시적인 궁중 존대를 포함합니다.
새 압축 자산은 **4,211바이트**이며 추가 런타임 라이브러리가 필요하지 않습니다.
이 데이터는 생성 모델의 출력을 정답으로 되먹임한 결과나 신경망 재학습이 아닙니다.

개정별로 새 항목만 추가하므로, 사용자가 삭제한 이전 개정의 기본값을 되살리지
않습니다. 기존 사용자 문장·용어는 유지합니다. `--no-learning`은 모든 교정 기억을
비활성화합니다. 전체 문장 일치는 문장 안의 임의 부분 문자열 교체를 허용하지 않습니다.

`陛下/殿下/閣下`는 원문 첫 호칭이 명확하고 한국어 호칭이 누락된 경우에만
복원합니다. 가족관계도 원문 첫 주어와 번역문의 첫 관계어가 명확하고 다른 가족이
함께 언급되지 않은 경우에 한정합니다. 예를 들어 `弟は`를 `아빠는`으로 잘못
번역했을 때 `남동생은`으로 교정합니다. `兄/姉`의 한국어 호칭을 화자 성별로
추측하거나, `娘`의 문맥별 의미를 하나로 고정하지 않습니다.

사용자 제공 ezTrans 자료의 14,946개 전이 규칙은
[별도 구문 분석](legacy-rule-syntax.md)을 마쳤습니다. 분석 결과 한국어→일본어
방향의 증거가 있어 일본어→한국어 신경망이나 교정 기억에 뒤집어 넣지 않았습니다.
이번 일본어→한국어 보정은 별도로 작성한 소스 조건이며 원본 VM 실행이 아닙니다.

## 평가 방법과 한계

[128개 평가 원문](../tests/fixtures/natural_language_review_ja.txt)은 축약형,
진행·완료, 금지·허용·의무, 부정, 존대, 감정, 복문, 인명·수량·시간,
가족관계와 표현 자체를 언급하는 반례를 포함합니다. 이 문장들은 기본 교정
기억의 정답 목록에 포함되지 않았다는 자동 검사를 거칩니다. 아래 모델·저장 실측은
`8340446`의 실행 파일 기준입니다. 이후 기본 교정의 중복 3개를 새 표현으로
교체했으며, 실측은 교정 기억을 비활성화한 조건이므로 해당 데이터를 사용하지
않습니다. 새 기본값은 별도의 실제 CLI 검사에서 확인했습니다.

`examples/review_natural_text.rs`는 같은 고정 모델을 사용해 기존 v0.3.5 기준 Linux
실행 파일과 수정 실행 파일을 각각 새 프로세스로 실행합니다. 내부 엔진, 32개 문맥,
교정 기억 없음, 원문 출력 없음 조건으로 비교하며 모델·입력·실행 파일 SHA-256과
모든 문장의 전후 결과를 기록합니다. 출력 변경 수는 정확도나 유창성 점수가 아닙니다.

[전체 비교 결과](natural-language-review-results.json)에서 128문장 중 37문장의
출력이 달라졌습니다. 다음은 확인 가능한 변화의 일부입니다. 첫 예처럼 호칭·말투를
고쳐도 다른 오역이 남는 경우를 함께 공개합니다.

| 원문 | 기존 출력 | 수정 출력 |
| --- | --- | --- |
| `「ありがとう、助かったよ！」` | `“감사합니다, 제가 구해 주셨어!”` | `“고마워, 제가 구해 주셨어!”` |
| `「うん、もう平気だよ。」` | `“그렇습니다, 이제 괜찮아.”` | `“응, 이제 괜찮아.”` |
| `「弟は外で走ってるよ。」` | `“아빠는 밖으로 달리고 있지요.”` | `“남동생은 밖으로 달리고 있어.”` |
| `「陛下、申し訳ございません。」` | `“우리 위대함, 미안해요.”` | `“폐하, 죄송합니다.”` |
| `「妹は図書館で待ってるよ。」` | `“내 아내는 도서관에서 기다리고 있어.”` | `“내 여동생은 도서관에서 기다리고 있어.”` |
| `「妹もその本を読んじゃったよ。」` | `“그럼 저도 그 책을 읽어봤어.”` | `“여동생도 그 책을 읽어버렸어.”` |

초기 72문장 비교에서 `飲んじゃだめ/入っちゃだめ/食べちゃだめ`를 일반형으로
확장해도 금지 의미가 회복되지 않거나 악화됐습니다. 해당 확장은 제외했습니다.
`帰ってない` 확장으로 이동 방향·존대가 바뀐 경우와, `やってません` 확장으로
말투가 나빠진 경우도 제외했습니다. 따라서 문법적으로 가능한 전처리라는 이유만으로
모든 규칙을 채택하지 않았습니다.

128문장으로 확대한 비교에서는 `遊んじゃった` 확장이 과거를 현재로 바꾸고,
`飲んでます` 확장이 진행을 미래 의사로 바꾸는 사례도 확인했습니다. 새로 추가했던
완료의 미래형 확장과 `待ってません` 확장도 제외했습니다. 완료 후처리에서는
`てみ/でみ`, `ことが/ことは`, 중첩 인용이 함께 있는 경험·복합 문맥을 보호합니다.

아래는 채택하지 않은 전처리의 실제 출력입니다. 기존 출력도 틀린 경우가 있으므로
전처리를 제외했다는 사실을 해당 문장의 문제가 해결됐다는 뜻으로 사용하지 않습니다.

| 원문 | 시험한 확장 | 기존 출력 | 제외한 후보 출력 |
| --- | --- | --- | --- |
| `「もう食べちゃだめなの？」` | `食べてはだめ` | `“너 이제 먹지 않아?”` | `“너 이제 먹어도 안 먹어?”` |
| `「子供たちは外で遊んじゃったよ。」` | `遊んでしまった` | `“어린이들이 밖에서 놀고 있었어.”` | `“어린이들이 밖에서 놀고 있어.”` |
| `「今は水を飲んでます。」` | `飲んでいます` | `“오늘은 물을 마시나요?”` | `“오늘은 물을 마시겠어요?”` |
| `「彼女はまだ私を待ってません。」` | `待っていません` | `“그녀는 아직 나를 기다리지 않는다.”` | `“그녀는 아직 나를 기다리지 않았어요.”` |

기본 모델에는 금지와 허용을 혼동하거나, 주체·방향·시제를 잘못 번역하는 사례가
남아 있습니다. 호칭이나 종결어미 개선만으로 문장 전체가 정확해졌다고 판정하지
않습니다. 이 검토는 전문 번역가의 문서 단위 평가나 인간 수준의 품질 인증이 아닙니다.
Windows의 실제 ezTrans DLL 실행과 GPU 품질·속도는 이 Linux 환경에서 검증하지
못했습니다. 전체 작품 저장 검증은 의미 정확도 평가와 구분합니다.

## 실행 검증

- 기본 GUI 기능 테스트: 전체 GUI·CLI·세션·저장 통합 테스트와, 중복 수정 후
  라이브러리 123개 및 공통 언어 처리 통합 테스트 통과.
- 선택적 `legacy` 기능: 라이브러리 139개와 CLI·공통 처리·저장 테스트 통과.
  외부 자료가 필요한 기본 제외 테스트는 별도로 구분했습니다.
- 새 180개 기본 표현을 실제 CLI로 대조했습니다. 선택적 `legacy`의 native 빌드와
  기본 내부 모델 빌드 모두 검토한 목표 문장과 180개 전부 일치했고, 읽기만으로
  사용자 교정 파일이 생성되지 않았습니다. 이는 기본값 적용 검사이며, 새로운
  문장의 모델 번역 품질 검사와 구분합니다. 원본 ezTrans DLL을 실행한 검사는 아닙니다.
- 고정 실제 모델 테스트: 순차/병렬 결과 일치, 256개까지의 문맥 재사용·순서,
  사용자 교정 우선순위 2개 및 교정 기억 없는 대화 회귀 1개 통과.
- `gui,legacy` 전체 대상 Clippy `-D warnings` 통과. 배포 의존성 감사는 기존과
  같은 255개 크레이트로 통과했습니다. 새 인터프리터·학습·GPU 라이브러리는 없습니다.
- [작품 저장 결과](natural-language-save-verification.json): 고정 로컬 HTML을
  사용한 35화 전체 6,248행, 24화 전체 17,041행의 원문·목차·번역 대응과
  문단 경계가 모두 검증됐습니다. 작품 본문은 Git이나 릴리스에 포함하지 않았습니다.

작품별 새 프로세스 1회 측정은 49.3337초/73.9419초였습니다. 모델 로드·해시 검증·
파싱·표제와 본문 번역·TXT 최종 저장을 포함하며, 추론 중 다른 빌드나 모델 테스트를
병행하지 않았습니다. 같은 4-CPU Linux 호스트의 저장 회귀 측정이므로 PC 평균,
네트워크 다운로드 속도, 새 70%/90% 성능 달성의 증거로 사용하지 않습니다.

재현 명령의 모델과 이전 실행 파일은 별도로 준비해야 합니다. 아래 비교 도구는
모델을 다운로드하거나 학습하지 않습니다.

```sh
cargo test --locked --release --features gui --lib --bins --tests
cargo test --locked --no-default-features --features legacy --all-targets
cargo clippy --locked --features gui,legacy --all-targets -- -D warnings
SYOUSETU_MODEL_DIR=LOCAL_MODEL CANDLE_NUM_THREADS=1 cargo test --locked \
  --release --features gui --test offline_model --test dialogue_quality -- --ignored
cargo run --locked --release --example review_natural_text -- \
  BASELINE_LINUX_CLI CANDIDATE_LINUX_CLI LOCAL_MODEL \
  tests/fixtures/natural_language_review_ja.txt OUTPUT_DIR
```

## 검토에 사용한 자료

- [Sennrich 등, Controlling Politeness in NMT (2016)](https://aclanthology.org/N16-1005/):
  말투 제어는 학습된 조건과 관계가 있습니다. 학습하지 않은 제어 토큰을 임의로
  추가하는 대신 명시된 원문 말투에 한정해 종결을 처리했습니다.
- [Voita 등, When a Good Translation is Wrong in Context (2019)](https://aclanthology.org/P19-1116/):
  지시·생략·어휘 결속 문제 때문에 문장 단위의 유창함만으로 문맥 정합성을
  보장할 수 없습니다. 관계어·복문·부정 범위 반례와 화자 정보 추측 제한에 반영했습니다.
- [Freitag 등, Experts, Errors, and Context (2021)](https://aclanthology.org/2021.tacl-1.87/):
  MQM 기반 오류 분석과 전문 평가의 중요성을 반영해, 변경 문장 수나 파일 구조
  통과를 번역 품질 수치로 바꾸지 않았습니다.

최신 엔진·속도 대안과 실측 제한은 [별도 엔진 검토](engine-backend-review.md)에
있습니다. 이번 품질 변경을 90% 속도 단축 달성으로 제시하지 않습니다.
