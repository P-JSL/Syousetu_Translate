# 클라우드에서 측정한 SMaLL-100 INT8 첫 번역 시간

2026-11-18 (한국시간). 현재 실행 파일로 Kakuyomu 작품 35화 전체를
처음부터 번역하고 TXT에 저장하는 데 **45.975~46.477초**가 걸렸다.
기존 실행 파일 두 번의 중앙값은 **46.226초**다. 두 CPU 가속 후보는
각각 대조 실행보다 1.28%, 4.15% 오래 걸려 제거했다.
[측정 작품](https://kakuyomu.jp/works/11054822663814504924)

| 비교 | 기존 시간 | 후보 시간 | 시간 증가 | 기존 peak RSS | 후보 peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 어휘 투영에서 12행이 가중치를 공유 | 46.476602020초 | 47.072534070초 | 1.28% | 1,315,036 KiB | 1,256,100 KiB |
| AVX-512로 Q8 입력을 한 번에 준비 | 45.975167284초 | 47.882417840초 | 4.15% | 1,220,460 KiB | 1,260,252 KiB |

첫 후보는 넓은 어휘 투영에서 한 가중치 블록을 최대 12개 입력 행에
사용한다. 모든 어휘를 평가하며 각 점수의 정수 내적과 FMA 누적 순서를
유지한다. 두 번째 후보는 같은 블록 스케일과 반올림 규칙으로 오프셋
부호화를 패킹에 합친다. Q8 내적이 사용하지 않는 부분합 계산과 부호를
변환하는 추가 순회를 줄인다. 두 후보 모두 행렬 점수 회귀 시험을 통과했다.

## 측정 조건과 결과 검증

- AMD EPYC 9V45, CPU 할당량 4개, 기본 AVX-512 VNNI. 병렬 번역의 논리
  문맥은 128개이며 `CANDLE_NUM_THREADS=1`이다. 이 클라우드에 NVIDIA
  장치가 없어 RTX 4070 이상의 가속률은 실측하지 못했다.
- 최신 대조 소스는 `9e9a877be37e17b227769d0f4a8171d1570b77cd`다.
  후보별로 대조와 후보를 한 번씩 새 프로세스에서 실행했다. 교정 기억과
  디스크 번역 결과 재사용을 끄고, 같은 HTML 사본과 모델을 사용했다.
  모델 무결성 검증·로드와 순서대로 저장하는 TXT 쓰기는 시간에 포함했다.
  HTML 네트워크 다운로드는 제외했고 OS 파일 캐시는 비우지 않았다.
  실행 중 빌드나 다른 번역 작업을 병행하지 않았다.
  [측정 코드](../examples/benchmark_first_translation.rs)
- 네 TXT가 모두 607,026바이트로 같았다. 파일을 직접 비교했고, 별도
  검증기로 35화와 원문 6,248줄, 번역의 저장 순서를 확인했다. SHA-256은
  `a01ef9cac141faa625e740b353a6c2ed8800c9cec58f68e8fa5599fe879007bb`이다.
  [TXT 검증 코드](../examples/verify_saved_novel.rs)
- 10ms 간격으로 표본을 얻은 peak RSS는 첫 후보가 57.55 MiB 감소하고
  두 번째 후보가 38.86 MiB 증가했다. 각 후보는 검토 기준인 최대
  +512 MiB와 +25% 이내였다.

이전 v0.3.2의 35화 기록 163.1107초에 비해 현재 중앙값은 **71.66% 짧다**.
이는 서로 다른 시점의 버전 기록을 비교한 값이다. 최신 실행 파일을 기준으로
한 이번 두 후보에서는 추가 단축을 확인하지 못했다. 85~95% 추가 단축의
목표 시간은 약 6.93~2.31초다.
[v0.3.2 기준 기록](cpu-batching.md#v035-full-work-measurements)
