# 첫 번역 90~95% 단축을 위한 병목 확인

2026-11-17(KST), v0.3.6 공개 후 개발 소스에서 확인했습니다. **첫 번역의
90~95% 시간 단축은 아직 달성하지 못했습니다.** 완료 결과 재사용의
98.7~99.1% 개선은 [별도 재번역 시험](result-reuse.md)의 결과입니다.
두 수치를 섞거나 기존 개선 배수에 다시 곱하지 않습니다.

후속 [INT8 보정 연산 사전 계산](first-translation-offset.md)은 디스크 재사용을
완전히 끈 전체 작품의 반복 비교이며, 이 진단과 별도로 기록했습니다.

[K/V 저장 방식 후속 검토](first-translation-kv.md)는 품질과 메모리 허용 범위를
함께 확인했으나 24화의 속도 회귀로 적용하지 않았습니다. 최신 목표의 기준은
기존 SMaLL-100 INT8 실행 파일이며, 측정은 조건별 최대 2회로 제한합니다.

[AVX2 호환 경로 후속 최적화](first-translation-avx2.md)는 같은 모델의 전체
35화 첫 번역을 한 번씩 비교해 65.5% 단축과 TXT 동일성을 확인했습니다.
VNNI 경로 및 전체 PC의 평균 개선율로 일반화하지 않습니다. 85~95% 목표는
아직 미달입니다.

[기본 VNNI 경로 후속 검토](first-translation-native-followup.md)에서는 전체
35화 한 쌍의 차이가 0.5%에 그쳐 M7 실험 커널을 제거했습니다. 어휘 경로
보정의 중복 계산과 측정 횟수를 줄였으며, 이를 목표 달성으로 계산하지 않습니다.

## 측정 범위와 결과

AMD EPYC 9V45, CPU 예산 4개, GPU 없음, 논리 문맥 128개, 병렬 정책 고정입니다.
교정 기억과 디스크 결과 재사용을 끄고, 캐시한 HTML의 전체 35화/24화를
각각 새 프로세스로 번역했습니다. 네트워크 다운로드 시간은 제외됩니다.
모델 검증·로드부터 최종 TXT 저장·프로세스 종료까지 측정했습니다.
다른 빌드나 모델 시험은 추론과 병행하지 않았습니다.

이번 기록은 각 작품 **진단 빌드 1회**이며 가속 전후 비교나 production 지연
추정치가 아닙니다. 계측 비용과 실행 간 변동이 포함됩니다. 소스 파일·실행 파일·
모델 SHA, 모든 단계의 호출 수·시간과 독립 출력 검증은
[원자료 JSON](first-translation-profile.json)에 보관했습니다.

| 항목 | 35화 | 24화 |
| --- | ---: | ---: |
| 전체 프로세스 시간 | 67.3925초 | 80.6049초 |
| 인코더 시간 | 28.7018초 | 36.0315초 |
| 디코더 시간 | 33.4349초 | 41.5318초 |
| 전체 어휘 투영·선택 시간(디코더 내부) | 17.8821초 | 22.1102초 |
| KV 재연결 횟수(K/V 쌍 단위) | 224,472회 | 350,895회 |
| KV 재연결 스코프 시간 합 | 4.1991초 | 3.9270초 |
| KV 재연결의 목적지 payload 누계 | 32,938,131,456바이트 | 30,170,185,728바이트 |
| 프로세스 peak RSS 표본 | 1,402,980KiB | 1,385,328KiB |

중첩 단계의 시간은 겹치므로 모두 더하지 않습니다. 특히 여러 작업자의 KV
스코프는 서로 겹칠 수 있어, 시간 합을 그대로 전체 시간의 점유율로 해석하지
않습니다. 바이트 수는 두 `Tensor::cat` 목적지에 기록하는 tensor payload 합이며
실제 DRAM 트래픽, 최대 상주량이나 할당 비용 전체를 뜻하지 않습니다.

두 전체 TXT는 앞서 계측 없이 만든 각 작품의 대조 결과와 바이트 단위로
같았습니다. 별도 `verify_saved_novel`로 35화의 원문 6,248행과 24화의
17,041행, 회차·문단·저장 순서와 비어 있지 않은 번역을 확인했습니다.
출력 동일성과 구조 검증은 의미 정확성이나 모든 문장의 자연스러움을 보증하지 않습니다.

## 수학적 판단과 적용 여부

길이 T의 KV를 매 토큰 다시 연결하면 복사 payload는
`1 + 2 + … + T = T(T+1)/2`에 비례합니다. 저장 공간의 사전 할당은 이 복사
자체를 줄일 여지가 있지만, attention과 인코더·어휘 투영 계산은 그대로 남습니다.

전체 가속은 Amdahl 모형 `1 / ((1-f) + f/s)`를 따릅니다. 위 KV 시간 합을
전부 직렬 전체 시간이라고 간주하는 후한 단순 모형에서도 제거 후보는 약
6.23%/4.87%입니다. 실제로는 스코프 중첩, 메모리 접근과 스케줄링 상호작용을
따로 측정해야 합니다. 이 수치를 KV 변경의 실측 가속률로 제시하지 않습니다.

기존 v0.3.2 기준 전체 시간의 90% 목표는 35화 16.3111초/24화 26.3902초,
95% 목표는 8.1555초/13.1951초입니다. 현재 계측의 인코더 시간만으로도 이
전체 목표보다 길어, 디코더의 작은 부분만 없애서는 목표에 도달하지 못합니다.

따라서 S-08의 측정 우선 조건에 따라 **KV 저장 형식과 attention 연산은
변경하지 않았습니다.** 먼저 인코더·FFN 및 전체 어휘 투영이 더 큰 비용임을
확인했습니다. 기본 production에는 새 타이머·카운터·파일을 추가하지 않았습니다.

## 추가 자료 검토

- [PagedAttention](https://arxiv.org/abs/2309.06180)의 초록에서 확인한 2~4배는
  큰 LLM serving에서 메모리 단편화·복제·배치 제약을 개선한 결과입니다.
  현재의 짧은 문장·단일 beam·독립 KV를 사용하는 CPU 번역기에 그 배수를
  적용하지 않습니다. 현재 측정으로는 페이징 구현을 우선할 근거가 부족합니다.
- [TEAL](https://arxiv.org/abs/2408.14690)의 초록은 Llama/Mistral에서 작은
  활성값을 생략해 40~50% 희소성과 최대 1.53~1.8배 가속을 보고하면서
  성능 저하가 최소 수준이라고 기술합니다. **출력 보존 방식이 아니며**
  SMaLL-100의 품질·CPU 배치 가속 근거가 없어 기본 모델에 적용하지 않았습니다.
- 검증을 동반한 lookahead와 speculative decoding의 전제·수식 및 현재
  CPU 전체 어휘 연산의 비용은 [기존 연구 검토](inference-research-2026-11.md)에
  정리돼 있습니다. 호환 drafter와 실제 수용률·검증 비용 없이 가속을 가정하지 않습니다.

이 검토는 위 논문들의 전체 실험을 재현한 결과가 아닙니다. 가중치나 어휘를
임의로 제거하지 않고, 다음 후보도 전체 저장 시간과 번역 출력·의미를 함께
비교해야 합니다. GPU와 여러 사용자 PC의 평균 성능은 이 환경에서 미검증입니다.

## 재현

```sh
cargo build --locked --release --features gui,inference-profile --bin syousetu-translate
CANDLE_NUM_THREADS=1 target/release/syousetu-translate download \
  --url WORK_URL --html INDEX_HTML --episode-html-dir EPISODE_DIR \
  --start 1 --end CHAPTERS --out NEW_TXT --model-dir MODEL_DIR \
  --no-learning --no-result-cache --parallel-mode parallel --jobs 128 \
  --japanese --no-delay
```

`INFERENCE_PROFILE`는 stderr에 원문 없이 출력됩니다. `kv_append.copied_bytes`는
연결할 기존 K/V와 새 K/V의 `elem_count × dtype 크기` 합입니다. 배치 경로와
순차 경로를 모두 계측하며, `inference-profile`이 없으면 해당 코드가 제외됩니다.
